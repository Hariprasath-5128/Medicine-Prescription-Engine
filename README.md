# Medicine Prescription Engine

Evidence-grounded medication decision support. Symptom text goes in; a candidate
condition, ranked associated medications, and **numbered citations that resolve
to their original source URLs** come out — or an explicit "unverified" marker
when no evidence supports the suggestion.

> Research and educational decision support only. Output is generated by
> statistical models and is **not a prescription**. It carries no dose, route,
> frequency, duration, contraindication or interaction check, and must be
> reviewed by a qualified clinician before any clinical use.

## Read this first

The intended Kaggle dataset (`medical-conditions50000`) advertises 50,000 rows.
**It has 20**, copy-pasted 2,500 times each. Training on it produces a ~100%
accuracy score that is pure label leakage. Verify in one command:

```bash
python scripts/01_audit_dataset.py "data/raw/medical_question_answer_dataset_50000.csv" \
    --text-col "Symptoms/Question" --label-col "Disease Prediction"
# VERDICT: UNFIT for supervised training
```

It has been replaced with **95,456 deduplicated real patient reviews** across 90
conditions and 2,044 drugs. Full reasoning and measured numbers:
[docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md).

## Architecture

```
user text
   │
   ├─► safety triage ─────────► red-flag terms short-circuit to "seek care now"
   │
   ├─► recommender (PubMedBERT, two heads on one encoder)
   │      ├─ condition head : softmax over 90 conditions
   │      └─ drug head      : sigmoid over 2,044 drugs (multi-label)
   │
   ├─► retriever (bge-m3 → Chroma, cosine distance ≤ 0.55)
   │      └─ chunk + section + relevance + source_url, or nothing
   │
   └─► Recommendation + numbered citations, or an explicit UNVERIFIED marker
```

The retriever **confirms** what the recommender proposed; it never supplies the
recommendation. When nothing clears the distance threshold the answer says so
rather than presenting a weak match as evidence.

## Cloning (Git LFS required)

The processed datasets are stored with **Git LFS**, so install it before cloning
or the data files arrive as small text pointers instead of real content:

```bash
git lfs install
git clone https://github.com/Hariprasath-5128/Medicine-Prescription-Engine.git
```

Already cloned without LFS? `git lfs pull` fetches the real files.

**What is in the repo:** the deduplicated, leakage-checked splits the models
actually train on (`data/processed/`, ~582 MB via LFS). These pin the exact data
behind every reported metric.

**What is not:** `data/raw/` (re-downloaded by `scripts/02_prepare_data.py` from
Kaggle), `data/chroma/` (copied from SERA by `scripts/00_setup_evidence_db.py`),
and `artifacts/` (regenerated by the training scripts).

> the two training stages share no files and run in parallel.
>
> **Per-step guide: [docs/RUNBOOK.md](docs/RUNBOOK.md)** - what each command does,
> what success looks like, and what to do when it fails.

## One-day run (RTX 5070, 12 GB VRAM / 24 GB RAM)

```bash
python scripts/run_all.py --hours 24
```

Runs every stage in order, handing each one the hours actually remaining. Cheap
work runs first, so an overrun costs the *optional* QA fine-tune rather than the
whole system. Every training stage **measures real throughput on your GPU** and
subsamples if the full run would not fit - no estimate is trusted, because an
estimate taken from the wrong card was wrong by an order of magnitude once
already (see docs/IMPLEMENTATION_PLAN.md).

| Stage | Budget | GPU | Optional |
|---|---|---|---|
| Evidence DB | minutes | no | no |
| Data prep | ~15 min | no | no |
| Recommender (BioLinkBERT-large) | ~3 h | yes | no |
| QA QDoRA (Llama-3-8B) | the remainder | yes | **yes** |
| Evaluation | ~20 min | partly | no |

`--skip-qa` runs only the parts the API and UI need; `--small` swaps the 8B for
Phi-3-mini; `--dry-run` prints the plan without executing.

## Build order

```bash
# 0. Copy the SERA evidence index (56,407 chunks, ~632 MB)
python scripts/00_setup_evidence_db.py --verify

# 1. Audit any dataset before trusting it
python scripts/01_audit_dataset.py data/raw/<file>.csv --text-col review

# 2. Download and clean the real training data
python scripts/02_prepare_data.py --all

# 3. Train the recommender  (BioLinkBERT-large: 6.71 GB at batch 8, measured)
python scripts/03_train_recommender.py                       # large, 12 GB box
python scripts/03_train_recommender.py --batch-size 4 --fp16 # 3.01 GB, 4 GB card
python scripts/03_train_recommender.py --encoder base        # 110M fallback

# 4. DoRA QA fine-tune  (12 GB card - check the environment first)
python scripts/04_train_qa_dora.py --check
python scripts/04_train_qa_dora.py --small     # Phi-3-mini
python scripts/04_train_qa_dora.py             # Llama-3-8B-UltraMedical

# 5. Evaluate
python scripts/05_evaluate.py --all

# 6/7. Serve
uvicorn src.api.main:app --reload --port 8000     # http://127.0.0.1:8000/docs
streamlit run src/ui/app.py
```

Everything except step 4 runs on a 4 GB card.

## Models

| Stage | Model | Why |
|---|---|---|
| QA fine-tune | `TsinghuaC3I/Llama-3-8B-UltraMedical` | Outperforms Meditron-70B on MedQA/MedMCQA/PubMedQA |
| QA dataset | `TsinghuaC3I/UltraMedical` | 409,593 rows, 96.07% distinct → 181,700 pairs kept |
| QA fallback | `microsoft/Phi-3-mini-4k-instruct` | Comfortable in 12 GB |
| Recommender | `michiyasunaga/BioLinkBERT-large` | **SOTA on BLURB / MedQA-USMLE**, 335.7M params. Pretrained on PubMed *with citation links*. Swap via `--encoder base\|biomedbert` |
| Embeddings | `BAAI/bge-m3` | Must match the SERA index |

Meditron-7B was **not** chosen: it is Llama-2-era, and independent 2026
evaluation ranked Meditron-70B last among 70B models on a neurology board exam.

## Testing

```bash
pytest tests/ -v     # 12 tests; model-dependent ones skip when untrained
```

The suite guards the failure that started this project: `test_training_data_has_
real_variation` fails if a templated dataset is ever swapped back in, and
`test_processed_splits_do_not_share_text` fails on any train/test leakage.

## Limitations

- **The corpus is disease-information text** (MedQuAD / MedlinePlus / Genetics
  Home Reference), not PubMed abstracts and not drug trials. Do not describe this
  as "PubMed RAG" — the source URLs are `nlm.nih.gov`. It can confirm a condition
  is described as stated; it is not drug-efficacy evidence.
- **Grounding is measured, not assumed.** 50/50 sampled conditions retrieve
  supporting evidence (100%), because the corpus includes MedlinePlus, not only
  genetics material. Re-check with `scripts/05_evaluate.py --grounding` if you
  swap the corpus - a retrieved chunk still only confirms the *condition*, not
  the drug choice.
- **Association is not prescription.** The drug head learns what patients wrote
  reviews about, so popular drugs are over-represented.
